# 建檔交派給 subagent

步驟 5 的建檔與步驟 6 的矛盾比對，要讀分類子索引、既有知識與 `kb-reconcile.sh` 的輸出，量大但不需要對話脈絡。這段交給 subagent，主對話只收建檔結果。

## 分工

| 步驟 | 執行者 | 原因 |
|---|---|---|
| 1. 前置檢查 | 主代理 | 一支腳本，結束碼決定要不要往下 |
| 2–3. 判定來源、判斷候選 | 主代理 | 入口 B 的來源是對話本身，subagent 看不到對話記錄 |
| 4. 徵詢使用者 | 主代理 | Claude Code 會從所有 subagent 移除 `AskUserQuestion`，subagent 無法徵詢 |
| 4. 免詢問自動收錄：確認開關、判定條件 2–5、10 則計數 | 主代理 | 條件要對照對話才判斷得了；計數跨多次交派 |
| 5. 免詢問候選的條件 1 複核（全新、無重複） | subagent | 要讀分類子索引與既有知識；只能把候選降為「需徵詢」，不能反過來 |
| 5. 建檔 | subagent | 只處理主代理交付的候選，依各自的寫入依據安裝 |
| 6. 比對新舊矛盾；過時、錯誤的段落改寫 | subagent | 不需徵詢；衝突與整份不成立只回報，不執行取代 |
| 6. 衝突的徵詢；執行 `kb-supersede.sh`、`kb-delete.sh` | 主代理 | 衝突需要徵詢；移動與刪除知識檔只由主代理執行 |
| 7. 回報 | 主代理 | 轉述 subagent 的結果 |

權限提示（permission prompt）不能代替步驟 4 的同意：它只有允許／拒絕單一工具呼叫，且 bypass 模式下根本不會出現。

## 何時交派

- 目前工具能派出 subagent（Claude Code 為 `Agent` 工具）→ 交派。
- 不能派出，或 subagent 失敗、回報不完整 → 主代理依 `SKILL.md` 步驟 5、6 自行執行。`kb-new.sh` 會擋下已存在的目標，已建好的那幾則不會重複建立。

## Claude Code 的交派參數

| 參數 | 值 | 原因 |
|---|---|---|
| `subagent_type` | `general-purpose` | 要能跑 `Bash`、編輯草稿；`Explore` 是唯讀，不能用。不另裝自訂 agent 檔，安裝方式維持只裝三個 skill |
| `run_in_background` | `false` | 主代理要拿回報接著徵詢取代並回報 |
| `model` | 不指定 | 分類、合併與矛盾比對仍要判斷，沿用 session 模型 |

## 交派 prompt 範本

`<...>` 由主代理填入；`SKILL_DIR` 填此 skill 安裝目錄的絕對路徑。每則候選都要寫到 subagent 不必回頭看對話也能寫出 MADR 內容。

subagent 看不到對話，判斷舊知識過時或錯誤只能靠「依據」：本次驗證到、會推翻既有做法的事實（版本、介面、實測結果）要寫進去，沒寫的它只能當衝突回報。「來源」不填裝置的絕對路徑，寫資料夾名稱或專案根的相對路徑。

每則候選都要標「寫入依據」：使用者同意過的標 `已同意`；步驟 4 的免詢問條件 2–5 全過、開關開啟、且還在 10 則上限內的標 `免詢問`。免詢問候選的「依據」要寫明本次的驗證方式與結果，subagent 會原樣寫進 `## 驗證`。

```text
你負責把主代理交付的知識寫進共用知識庫。每則候選的寫入依據已在主對話判定：不要再徵詢，也不要問使用者任何問題。

## 路徑
- SKILL_DIR：<knowledge-record-skill 的絕對路徑>
- TOOLS：<SKILL_DIR>/../knowledge-tools-skill/scripts
- 來源（填 --source 與「補充資訊」）：<入口 A 的任務資料夾路徑，或入口 B 的對話來源說明>

## 候選
### k1
- 寫入依據：<已同意｜免詢問>
- 標題：<...>
- 觸發時機：<...>
- 結論：<一句話：下次遇到同情境該怎麼做>
- 依據：<驗證方式、關鍵事實、踩過的坑；入口 A 可寫「細節見任務資料夾的 notes.md 與 report」>

## 做法
1. 讀 <SKILL_DIR>/SKILL.md 的「5. 建檔」與「6. 新舊矛盾」，照其中的分類規則、指令順序與填寫規則執行。其餘步驟已由主代理完成，跳過。
2. 決定路徑前先讀頂層與相關分類的 index.md；同主題已有知識檔就合併進該檔，再執行 kb-reindex.sh。
3. 新主題依序執行 kb-new.sh → 填寫草稿 → kb-promote.sh --yes --source "<來源>"。這是寫入依據為「已同意」的做法。
4. 寫入依據為「免詢問」的候選，先複核：同分類沒有相同觸發情境的知識（kb-reconcile.sh <分類前綴>）、不需要合併或改寫既有知識、不與既有知識衝突。全過才建檔，草稿的「## 驗證」寫明驗證方式與結果，安裝時把 --yes 換成 --auto（兩者不可並用）。任一項不過，或 kb-promote.sh 以結束碼 3、1 拒絕：不寫入、刪掉草稿目錄，列進回報的「需徵詢」。不得改用 --yes 安裝被擋下的候選，也不得把「已同意」的候選改用 --auto。
5. 「已同意」的候選與既有知識在同一觸發情境衝突時，照樣建立新檔，列進回報的「矛盾」。
6. 「已同意」的候選遇到舊知識屬於過時或錯誤時，先確認符合 SKILL.md 步驟 6「直接改寫的條件」：候選的「依據」寫得出是哪一項事實推翻它，否則當衝突。符合時只改寫被推翻的段落並補上改寫紀錄，列進回報的「改寫」；舊檔整份不成立的不要動，列進回報的「取代建議」。
7. 不執行 kb-supersede.sh、kb-delete.sh 與 kb-auto.sh，不手改任何 index.md 與 front matter 的「狀態」，不刪知識檔；除了第 6 點的段落改寫，不動候選以外的知識。
8. 內容不寫入機密、裝置的絕對路徑、工作用的專案名稱與內部網址。

## 回報格式（只回這幾行，沒有的項目寫「無」）
建立：<相對路徑>（k1，已同意）— <摘要第一行>
自動收錄：<相對路徑>（k3，免詢問）— <摘要第一行>
合併：<相對路徑>（k2）— <摘要第一行>
需徵詢：<候選編號>：<複核不過的原因，或腳本輸出摘要>
矛盾：<新檔相對路徑> ↔ <舊檔相對路徑>：<一句話說明衝突>
改寫：<舊檔相對路徑>：<過時／錯誤，一句話說明>
取代建議：<新檔相對路徑> → <舊檔相對路徑>：<過時／錯誤，推翻它的事實>
失敗：<候選編號>：<原因與腳本輸出摘要>
```

## 收到回報後

1. **矛盾**：依「原生互動選單路由」逐筆詢問「以新知識取代／保留舊知識」。取代 → `sh <TOOLS>/kb-supersede.sh <舊> <新> --yes`；保留 → `sh <TOOLS>/kb-delete.sh <新> --yes` 移除剛建的新檔。
2. **取代建議**：主代理對照對話確認推翻的事實確實在本次驗證過，成立就直接執行 `sh <TOOLS>/kb-supersede.sh <舊> <新> --yes`，不詢問；確認不了就當矛盾，照第 1 點徵詢。
3. **失敗**：可修正的（例如路徑不合法）由主代理依步驟 5 自行補做該則；修不了的連同原因回報使用者。
4. **需徵詢**：免詢問候選被 subagent 降下來的，依步驟 4 的選單徵詢；使用者同意後以 `--yes` 補做該則（主代理依步驟 5 自行執行，或標成「已同意」再交派）。不計入 10 則上限。
5. **回報**：依步驟 7 分別列出使用者同意後記錄的與自動收錄的（相對路徑加摘要第一行）、合併、改寫與取代，以及保留舊知識而未記錄的那幾則。
